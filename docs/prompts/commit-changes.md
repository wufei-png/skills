# 按意图提交与交付收尾

## 按意图分批提交

用于整理已有改动并创建本地提交。

```text
请将 <允许提交的改动> 按可独立验证的意图分批提交到本地。先盘点暂存、未暂存和相关未跟踪文件，保留范围外的工作区与暂存改动。
逐批只暂存本批内容，核对暂存差异并运行相关检查，再提交。若已有暂存范围与本批冲突，指出冲突并保留现有暂存内容。
报告每个提交的哈希、范围和验证结果，以及仍未提交的改动。
```

只提交现有暂存内容时，可直接使用下面的版本。

```text
请检查现有暂存差异并创建一个本地提交。以当前暂存区为完整提交范围，保留工作区内容和暂存选择。报告提交哈希和范围。
```

## 提交后评审与清稿

用于先确定本地提交基线，再评审、修复和清稿的交付。评审者需能调用 `review-agent` 和 `karpathy-guidelines`。

```text
本轮提交范围为 <现有改动>，验收依据为 <需求与验证方式>，清稿范围为 <交付文档>。
核对工作区与暂存区，保留范围外的改动。按意图分批核对暂存差异、验证并本地提交，记录首批提交前的基准和末批提交。
用 $consensus-change-review 对这段提交做独立只读评审，让 $review-agent 参考 $karpathy-guidelines，检查改动的必要性和可验证行为。你负责核实意见，修复采纳的问题，验证通过后单独提交。
最后用 $sanitize-artifacts 清理指定文档里的制作残留，保留读者需要的事实、使用限制和归属信息。核对后单独提交清稿改动。
汇总各批提交、评审结论、采纳的修复和对应验证。
```

仓库内的配套 Skill 为 [consensus-change-review](../../skills/engineering/consensus-change-review/SKILL.md) 和 [sanitize-artifacts](../../skills/productivity/sanitize-artifacts/SKILL.md)。
