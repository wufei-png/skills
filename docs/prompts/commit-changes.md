# 按意图提交与交付收尾

## 研判来源不明的工作区改动

```text
用 $worktree-triage 盘点当前 Git 工作区。原会话可能找不到，请依据现有证据推断每组改动的用途，给出去留建议和验证方式。
[可选] 直接完成。把证据充分且验证通过的改动按意图分批提交到本地，待定改动留在原处并和我讨论。
[可选] 我授权丢弃 <已确定的文件或差异范围>。
```

工作区研判和执行流程见 [worktree-triage](../../skills/engineering/worktree-triage/SKILL.md)。

## 按意图分批提交

```text
请将 <允许提交的改动> 按可独立验证的意图分批提交到本地。先盘点暂存、未暂存和相关未跟踪文件，保留范围外的工作区与暂存改动。
逐批只暂存本批内容，核对暂存差异并运行相关检查，再提交。若已有暂存范围与本批冲突，指出冲突并保留现有暂存内容。
报告每个提交的哈希、范围和验证结果，以及仍未提交的改动。
```

## 仅提交已暂存内容

```text
请检查暂存差异，直接用现有暂存内容创建一个本地提交。报告提交哈希和范围。
```

## 提交后评审与清稿

评审者需能调用 `review-agent`。

```text
本轮提交范围为 <现有改动>，验收依据为 <需求与验证方式>，清稿范围为 <交付文档>。
核对工作区与暂存区，保留范围外的改动。按意图分批核对暂存差异、验证并本地提交，记录首批提交前的基准和末批提交。
用 $consensus-change-review 只读评审该提交范围。你负责核实意见，修复采纳项，验证通过后单独提交修复。
最后用 $sanitize-artifacts 清理指定文档的制作残留，保留读者需要的事实、使用限制和归属信息。核对后单独提交实际清稿改动。
汇总各批提交、评审结论、采纳的修复和对应验证。
```

仓库内的配套 Skill 为 [consensus-change-review](../../skills/engineering/consensus-change-review/SKILL.md) 和 [sanitize-artifacts](../../skills/productivity/sanitize-artifacts/SKILL.md)。
